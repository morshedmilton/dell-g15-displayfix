## 1. Executive Summary

Adversarial testing by Challenger M1_2 identified two Medium-severity defects in the I/O and reporting subsystems of `scripts/diagnostics/stress_test.ps1`:
- **Defect 3 (Concurrency collision)**: Line 504 constructs report file names using `$startTimeUtc.ToString("yyyyMMdd_HHmmss")`. When concurrent or near-simultaneous test executions occur within the same clock second, identical file names are resolved, causing silent report overwriting and loss of test audit artifacts.
- **Defect 4 (Missing drive / output directory failure)**: Lines 287-289 execute `Test-Path $OutputDir` followed by `New-Item -Path $OutputDir -ItemType Directory -Force`. If `$OutputDir` resides on a non-existent drive volume (e.g. `Z:\...`), `New-Item` throws an uncaught `System.Management.Automation.DriveNotFoundException`. Under `$ErrorActionPreference = "Stop"` (configured at line 84), this immediately terminates the PowerShell session before baseline or stress testing can execute.

This document provides the exact code modifications, root cause traces, architectural considerations, and reproducible verification scripts to resolve both defects completely.

## 2. Defect 3: Concurrency Collision in Report Generation

### 2.1 Root Cause & Mechanism
In `scripts/diagnostics/stress_test.ps1` lines 504–506:
```powershell
# --- 6. Write JSON & Markdown Reports ---
$timestampStr = $startTimeUtc.ToString("yyyyMMdd_HHmmss")
$jsonReportPath = Join-Path $OutputDir "stress_test_report_${timestampStr}.json"
$mdReportPath = Join-Path $OutputDir "stress_test_report_${timestampStr}.md"
```

1. **Resolution Granularity**: The timestamp string format `"yyyyMMdd_HHmmss"` only has 1-second resolution.
2. **Concurrent Overwrite**: In multi-agent environments, parallel CI test runners, or automated batch validation sweeps (e.g., testing multiple display profiles or modes simultaneously), two processes launched in the same second share the identical timestamp string (e.g. `stress_test_report_20261105_113407.json`).
3. **Silent Loss of Audit Evidence**: The second process to finish calls `Set-Content -Path $jsonReportPath` and silently clobbers the JSON report generated by the first process. Challenger M1_2 empirically proved that launching 2 simultaneous jobs resulted in only 2 files instead of 4, leaving zero trace of Job 1's test run.

### 2.2 Proposed Code Fix
Include the automatic PowerShell variable `$PID` (the current process identifier) as a suffix in `$timestampStr`:

```powershell
$timestampStr = "$($startTimeUtc.ToString('yyyyMMdd_HHmmss'))_$($PID)"
```

### 2.3 Exact Code Replacement (Line 504)

```powershell
<<<< TARGET FILE: scripts/diagnostics/stress_test.ps1 (Line 504)
<<<< ORIGINAL CODE
$timestampStr = $startTimeUtc.ToString("yyyyMMdd_HHmmss")
==== PROPOSED REPLACEMENT
$timestampStr = "$($startTimeUtc.ToString('yyyyMMdd_HHmmss'))_$($PID)"
>>>>
```

### 2.4 Detailed Analysis & Impact
- **Collision Resistance**: Process IDs on Windows are guaranteed to be unique among all concurrently running processes. Two processes running in the same second will always have distinct `$PID` values, preventing any file clobbering.
- **Lexicographical Sortability**: Because the chronological timestamp prefix `yyyyMMdd_HHmmss` is preserved, directory file listings remain chronologically sortable by filename.
- **Pattern Matching Compatibility**: Downstream log aggregators or test cleanup scripts searching for `stress_test_report_*.json` remain 100% compatible.
- **Zero Overhead**: `$PID` is an intrinsic PowerShell engine variable; querying it requires zero P/Invoke calls and zero I/O operations.

## 3. Defect 4: Missing Drive / Output Directory Creation Failure

### 3.1 Root Cause & Mechanism
In `scripts/diagnostics/stress_test.ps1` lines 287–289:
```powershell
if (-not (Test-Path $OutputDir)) {
    New-Item -Path $OutputDir -ItemType Directory -Force | Out-Null
}
```

1. **Strict Error Action**: Line 84 configures `$ErrorActionPreference = "Stop"`.
2. **Missing Volume**: If `$OutputDir` is passed with an invalid drive letter (e.g. `-OutputDir "Z:\DisplayFix\logs"` where drive `Z:` is unmounted or non-existent), `Test-Path $OutputDir` evaluates to `$false`.
3. **Terminating Exception**: `New-Item -Path $OutputDir -ItemType Directory -Force` attempts to create the path, but the PowerShell filesystem provider cannot find drive `Z:`, throwing `DriveNotFoundException`.
4. **Crash Before Testing**: Because of `$ErrorActionPreference = "Stop"`, PowerShell halts immediately. No baseline measurements are taken, no stress testing occurs, and no fallback is attempted.

### 3.2 Proposed Code Fix
Wrap directory validation and creation in a structured `try/catch` block. If directory verification or creation fails for any reason (missing drive, permission denial, invalid path characters), catch the exception, emit a descriptive warning, fall back to `$env:TEMP\DisplayFix\logs`, and ensure the fallback directory exists.

### 3.3 Exact Code Replacement (Lines 287–289)

```powershell
<<<< TARGET FILE: scripts/diagnostics/stress_test.ps1 (Lines 287-289)
<<<< ORIGINAL CODE
if (-not (Test-Path $OutputDir)) {
    New-Item -Path $OutputDir -ItemType Directory -Force | Out-Null
}
==== PROPOSED REPLACEMENT
try {
    if (-not (Test-Path -LiteralPath $OutputDir -ErrorAction Stop)) {
        New-Item -Path $OutputDir -ItemType Directory -Force -ErrorAction Stop | Out-Null
    }
} catch {
    $fallbackDir = Join-Path $env:TEMP "DisplayFix\logs"
    Write-Warning "Failed to create or access OutputDir '$OutputDir': $($_.Exception.Message). Falling back to '$fallbackDir'."
    $OutputDir = $fallbackDir
    try {
        if (-not (Test-Path -LiteralPath $OutputDir -ErrorAction Stop)) {
            New-Item -Path $OutputDir -ItemType Directory -Force -ErrorAction Stop | Out-Null
        }
    } catch {
        Write-Warning "Failed to create fallback directory '$OutputDir': $($_.Exception.Message)"
    }
}
>>>>
```

### 3.4 Detailed Analysis & Impact
- **Resilience Against Invalid Drives**: If the user or an automated script specifies a non-existent drive (e.g. `Z:\...`, `X:\...`), the error is trapped cleanly.
- **Safe Fallback Target**: `$env:TEMP\DisplayFix\logs` resides on the system volume (typically `C:\Users\<user>\AppData\Local\Temp`), which is guaranteed to exist and is always writable by standard and elevated user sessions.
- **Consistent Downstream Path Usage**: Because `$OutputDir` is reassigned to `$fallbackDir`, subsequent operations in Section 6:
  - `$jsonReportPath = Join-Path $OutputDir "stress_test_report_${timestampStr}.json"`
  - `$mdReportPath = Join-Path $OutputDir "stress_test_report_${timestampStr}.md"`
  - Markdown audit metadata block
  - Console summary banner
  all seamlessly use the fallback directory path without further modification.
- **LiteralPath Protection**: Using `-LiteralPath` ensures that path strings containing brackets or wildcard symbols are treated as verbatim paths.
- **Nested Defensive Trap**: The secondary `try/catch` around `$fallbackDir` ensures that even in degraded environments, no uncaught exception can terminate the script during initialization.

## 5. Comprehensive Verification Strategy

### 5.1 Verification Test 1: Concurrency Collision Test (Defect 3)
**Objective**: Verify that two simultaneous executions of `stress_test.ps1` starting in the same second generate two distinct JSON files and two distinct Markdown files without overwriting.

**PowerShell Test Script**:
```powershell
$testDir = Join-Path $env:TEMP "test_concurrency_fix_$([Guid]::NewGuid().ToString('N'))"
New-Item -Path $testDir -ItemType Directory -Force | Out-Null

try {
    $scriptPath = (Resolve-Path "scripts\diagnostics\stress_test.ps1").Path

    # Launch two background jobs simultaneously targeting the same OutputDir
    $j1 = Start-Job -ScriptBlock { param($s, $d) & $s -Iterations 1 -Mode Simulated -OutputDir $d -Json } -ArgumentList $scriptPath, $testDir
    $j2 = Start-Job -ScriptBlock { param($s, $d) & $s -Iterations 1 -Mode Simulated -OutputDir $d -Json } -ArgumentList $scriptPath, $testDir

    $null = Wait-Job $j1, $j2
    $out1 = Receive-Job $j1
    $out2 = Receive-Job $j2

    $jsonFiles = Get-ChildItem -Path $testDir -Filter "*.json"
    $mdFiles = Get-ChildItem -Path $testDir -Filter "*.md"

    Write-Host "JSON Report Count: $($jsonFiles.Count)"
    Write-Host "MD Report Count:   $($mdFiles.Count)"

    if ($jsonFiles.Count -ne 2 -or $mdFiles.Count -ne 2) {
        throw "Verification FAILED: Expected 2 JSON and 2 MD reports, found $($jsonFiles.Count) JSON and $($mdFiles.Count) MD."
    }

    # Verify filenames include distinct PIDs
    $pidsInNames = $jsonFiles | ForEach-Object {
        if ($_.Name -match 'stress_test_report_\d{8}_\d{6}_(\d+)\.json') { $Matches[1] }
    }

    if ($pidsInNames.Count -ne 2 -or ($pidsInNames[0] -eq $pidsInNames[1])) {
        throw "Verification FAILED: Report filenames do not contain distinct process IDs: $($pidsInNames -join ', ')"
    }

    Write-Host "Verification PASSED: Concurrent runs generated separate reports with distinct PIDs." -ForegroundColor Green
} finally {
    Remove-Item -Path $testDir -Recurse -Force -ErrorAction SilentlyContinue
}
```

### 5.2 Verification Test 2: Missing Drive Fallback Test (Defect 4)
**Objective**: Verify that invoking `stress_test.ps1` with an invalid/missing drive letter falls back gracefully to `$env:TEMP\DisplayFix\logs`, prints a warning, and successfully generates report files without throwing an unhandled terminating exception.

**PowerShell Test Script**:

$allDrives = [System.IO.DriveInfo]::GetDrives().Name | ForEach-Object { $_[0].ToString().ToUpper() }
$unusedDrive = ('Z','Y','X','W','V','U' | Where-Object { $_ -notin $allDrives })[0]
if (-not $unusedDrive) { throw "Unable to find unused drive letter for test" }

$bogusOutputDir = "${unusedDrive}:\NonExistentDrive_$([Guid]::NewGuid().ToString('N'))\logs"
$fallbackExpectedDir = Join-Path $env:TEMP "DisplayFix\logs"

$scriptPath = (Resolve-Path "scripts\diagnostics\stress_test.ps1").Path

$warnings = [System.Collections.Generic.List[string]]::new()

$proc = Start-Process -FilePath "powershell.exe" -ArgumentList @(
    "-NoProfile",
    "-ExecutionPolicy", "Bypass",
    "-Command",
    "& { & '$scriptPath' -Iterations 1 -Mode Simulated -OutputDir '$bogusOutputDir' -Json }"
